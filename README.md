# Tennis research: устойчивые пороги k2 (ставка на второго игрока)

Поиск порогов коэффициента `k2` и дополнительных критериев по историческим матчам ATP с walk-forward
валидацией без утечки данных (time leak). Методология в машиночитаемом виде: `data/config.yaml`.

## Данные

- `data/raw/CRITERIA_DATA.xlsx` - исходный файл (26 листов). Не менять.
- `data/raw/ATP2026.xlsx` - сезон 2026 (вкладки `Sheet1`, `clay`), данные до 14 сентября.
- Исключены сводные листы `US_hard` (= `US_hard_feb` + `US_hard_summer`) и `WE_hard` (= `WE_hard_feb` + `WE_hard_oct`):
  точное совпадение по ключу Date+PL1+PL2. В расчёте 24 листа.

### win2 / win1

```
win == 0 (выиграл второй игрок): win2 = +100
win == 1 (выиграл первый игрок): win2 = -100 / (k2 - 1)
```
`win1` симметрично. Флэт-ставка 100.

## Метод расчёта порога (шаги 1-5)

1. Матчи окна сортируются по возрастанию `k2`, считается кумулятивная сумма `win2` по уникальным значениям `k2`.
2. Порог - значение `k2` с максимальной кумулятивной суммой при числе матчей под порогом не менее 300 (`k2 <= t`).
3. Если матчей под порогом больше 800 - второй критерий выбирается внутри отфильтрованных по `k2` матчей по колонкам F-P.
4. Если матчей не больше 800 - берётся весь пул, ищется пара: `k2 <= t2` плюс одна колонка F-P, дающая максимум.
5. На матчах после шага 3/4 выбирается ещё один порог вида `Surf p < x`.

Колонки F-P: Total rate, Surf p, 2m point, Surf1, Surf2, Total1, Total2, Poi_s1, Poi_s2, Poi_t1, Poi_t2.

Уровни фильтров: **F1** = шаг 2, **F2** = F1 + второй критерий (шаги 3-4), **F3** = F2 + `Surf p < x` (шаг 5).

### Защита от утечки (no leak)

Порог для года Y берётся только из окна, заканчивающегося годом Y-1 (например, для 2024 - окно «2017-2023 вкл»).
Окна: до 2020, до 2021, 2016-2022, 2017-2023, 2018-2024, 2019-2025. Оценка ведётся с 2021 года; окно 2019-2025 нужно для сезона 2026.

## Фильтр по ставкам (4-й фильтр)

Ставки (`curr_games`) - матчи сезона Y, прошедшие фильтры окна Y-1 (F1, F2 или F3). После каждого сезона ставки накапливаются
(2021, 2021-2022, ...), и по ним (а не по трейну) сканируются все критерии: колонки F-P в обе стороны и `k2 <` (строго).
Фильтр один на профиль (CLAY либо HARD_GRASS), без деления на группы. Выбранный по ставкам прошлых лет фильтр накладывается
на ставки следующего сезона и сохраняется во вкладке `curr_games_4filter` (для 2021 года истории нет - он не фильтруется).
Правило выбора: `k2` (лучший строгий `k2 <`, по умолчанию) либо строка ранжированного списка (`rank`).
Фильтр должен проверяться на ставках F1 и F3 (работает на любом уровне).

Ранжированный список - `BEST_BET_CRIT_<profile>.xlsx`: вкладки `CLAY2021-2021`, `CLAY2021-2022`, ...;
колонки `column | op | threshold | matches | sum_win2 | roi | pool_matches | pool_sum`.

## Группы

**Грунт:** `SAm_Eu_Clay` (SAm_clay, Eu_Clay); `Masters_RG` (Madrid, Monte-Carlo, Rome, RG_Q, RG).

**Хард и трава:** `ATP_hard_Masters` (WE_hard_feb, WE_hard_oct, US_hard_feb, US_hard_summer, Aus, Chn, US1000_march,
US1000_aug, Chn_masters, Paris); `GrandSlam_hard_grass` (AO, AO_Q, US_open, US_Q, Wimbledon, Wim_Q; квалификации Больших шлемов
относятся к шлемам); `ATP_grass` (grass).

### Сезон 2026: соответствие турниров и пропуски

Коэффициент `k2` = `op2` (открывающий). `Poi_s rate` -> `Surf p`, `poi_2m rate` -> `2m point`.
Не входят в исторические листы и пропускаются: Doha, Dubai, Acapulco, Hong Kong ATP, Los Cabos.
Полное соответствие турниров листам - в `config.yaml` (`season_2026.tournament_to_sheet`).

## Результаты (`data/processed/`)

- **Thresholds** - пороги по всем группам и 6 окнам (включая 2019-2025).
- **Results_by_tourn_sheet** - построчно по листу турнира и году (2021-2025): `prev.seasons` (сумма `win2` по отфильтрованным
  матчам всего обучающего окна года Y-1), `curr.season` (сумма `win2` за год Y), `threshold`, `prev_count`, `curr_count`.
- **curr_games** - ставки сезонов 2021-2025, прошедшие фильтры.
- **curr_games_4filter** - ставки 2022+, дополнительно отфильтрованные по критерию, выбранному на ставках предыдущих сезонов.

## Ноутбуки

1. `1.0-jm-three-filters.ipynb` - параметры `PROFILE` (`clay`/`hard_grass`) и `FILTER_LEVEL` (1/2/3). Считает пороги по 6 окнам,
   ставки и `Results_by_tourn_sheet`, сохраняет в `data/processed/`.
2. `2.0-jm-bet-filter-selection.ipynb` - принимает файл ставок (вкладка `curr_games`, 1, 2 или 3 фильтра), строит ранжированные
   списки по накопленным ставкам, применяет выбранный фильтр к ставкам следующего сезона (`curr_games_4filter`) и сохраняет
   проверку топ-N (`walk_forward_check`). Параметры: `PROFILE`, `BETS_FILE`, `RULE` (`k2`/`rank`), `RANK`, `MIN_BETS`.
